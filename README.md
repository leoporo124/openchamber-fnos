# OpenChamber for fnOS

OpenChamber 的飞牛 fnOS 原生部署与管理应用，支持 x86_64。

- **OpenChamber Admin**：服务启停、在线部署与更新、工作区、数据快照、日志和应用设置。
- **OpenChamber WebUI**：项目、模型配置和 AI 编程会话。
- 支持 `latest / canary` 更新渠道、飞牛统一网关、独立端口和访问密码。
- 安装可选 Data / Share 数据位置、Root / Package 运行用户。

## 使用

从 [GitHub Releases](https://github.com/leoporo124/openchamber-fnos/releases/latest) 下载 `openchamber-x86.fpk`，同页提供 SHA-256 校验文件。

1. 安装 `openchamber-x86.fpk`，按提示安装 `nodejs_v24`，确认系统 Git 可用。
2. 打开 **OpenChamber Admin**，在概览中联网部署运行环境。
3. 打开 **OpenChamber WebUI**，配置模型并选择项目。

当前 Admin 版本为 `0.1.9`。需要 Node.js `24.x >=24.14.0`；默认 Data + Root、`latest` 渠道。FPK 不含离线运行包。

更新保留配置和会话，失败时尝试恢复运行包；关键恢复未完成时保留记录并限制后续操作。非关键安装残留清理失败只记录警告，不无限占用维护锁。快照只备份应用数据，项目源码需另行备份；还原时若运行版本不同，先联网安装快照对应的精确版本，失败时回滚数据与运行包。普通部署和更新禁止降级。运行包回滚不等于回滚上游可能已执行的数据迁移，更新前仍应创建快照。

部署时所选国内 npm 镜像源直连，GitHub 等外部下载按网络代理设置连接；npm 支持 HTTP、HTTPS 和 SOCKS5。服务进程代理由独立开关控制，需要 HTTP 或 HTTPS 代理地址，同时向 OpenChamber、OpenCode、Git HTTPS 操作和 npm 子进程传递代理设置；自行指定网络配置的工具仍以其自身配置为准。Admin 新版本在侧栏显示更新徽章，点击前往 Releases 下载 FPK。

### 管理权限与状态同步

以下约定适用于 Admin `0.1.8`；旧版本需以其对应源码为准。

- 飞牛网关下的 Admin、管理 API 和 WebUI 均要求管理员身份；Socket 连接还须通过内核对端 UID 校验。当前信任 Root，以及 UID 为 1–999 的 `nginx`、`www-data` 系统账户。该账户约定尚需在目标 fnOS 上确认，不兼容时不会自动取消校验；排查见[反向代理说明](./REVERSE_PROXY_ADAPTATION.md#访问密码与来源校验)。
- 独立代理端口只提供 WebUI，不提供 Admin API。默认监听所有 IPv4 接口；访问密码留空时，该端口没有密码保护，应配置密码并限制防火墙访问范围。
- 设置读取返回 `revision`，保存携带 `If-Match`。其他页面保存或快照还原改变设置后，旧草稿不会直接覆盖新配置；界面保留草稿并提示重新加载。
- 工作区、快照列表及日志通过 WebSocket 初始化和更新，不再从浏览器存储恢复旧列表。日志通过序列检测补齐缺口，清空、轮转和缓冲溢出时重新同步最近 300 行。
- 首次连接及断线后留出 3 秒缓冲；持续无法建立实时连接时显示警告，连接恢复后自动移除，短暂重连不再闪出错误提示。
- 快照归档先写入临时目录，完成后再原子发布。中断归档在启动或下一次快照维护时清理；恢复记录未处理完成时，启动、保存设置和快照维护仍受限制。请在飞牛应用中心重启应用以重试恢复，不要手动删除恢复记录。

### 飞牛文件管理与网络代理

- 通过 NAS 的局域网 IPv4 地址以 HTTP 访问 WebUI 时，侧栏里的 `localhost` 快捷入口可用 NAS 的同一地址和服务端口打开。目标服务须已对局域网提供 HTTP 访问。HTTPS、飞牛中继和 OpenChamber Space 沿用上游预览行为。
- 在飞牛桌面内通过 **OpenChamber WebUI** 图标进入，项目菜单的「在文件资源管理器中打开」会调用飞牛文件管理器；文件定位会打开父目录。独立浏览器、独立端口或外部反代页面若未运行在飞牛宿主中，会提示从飞牛桌面进入，不会在 NAS 上调用 `xdg-open`。应用运行用户和当前飞牛登录用户均需有权访问该目录。
- WebUI 加载时即开始建立飞牛宿主连接；首次定位会等待连接就绪，连接较慢时最多等待 15 秒。若等待超时，连接仍会在后台继续，就绪后可在同一页面重试，不必关闭并重新打开 UI。
- Clash 代理示例：在 Admin「应用设置」填写 `http://192.168.0.105:7890`，开启「应用于服务进程」并保存。`7890` 须为 HTTP 或混合端口，Clash 须允许局域网连接、监听 `0.0.0.0` 或 NAS 局域网地址；Docker 桥接网络须发布该端口，NAS 防火墙须允许应用访问。其他安装环境请替换为实际代理地址。
- 保存运行时代理设置后，会重启运行中的 OpenChamber 及托管 OpenCode，正在执行的任务可能中断。HTTP 代理适用于 Git HTTPS 地址，不会接管 `git@github.com:...` 形式的 SSH 连接。
- 手动验证：打开项目目录与文件父目录，确认不存在目录和无权限目录有明确报错；在会话中分别验证 GitHub 网页读取、Git HTTPS 操作和 npm 安装，确认国内镜像及本机 OpenCode 连接不受影响。截图无法确认 Clash 实际监听和端口发布状态，需在 fnOS 上核对。
- 冷启动验证：重新登录飞牛桌面，不预先打开文件管理器，首次打开 WebUI 后立即定位项目目录；再验证关闭重开、连续定位和首次等待超时后的原页面重试。

## 构建

需要 Node.js 24、npm 和 Go 1.27.3 或更新的兼容工具链。Windows 执行 `build.cmd`，Linux x86_64 执行 `bash build.sh`，产物为 `fnpack/openchamber.fpk`。GitHub Actions 支持手动构建并发布 Releases，也可关闭发布选项只生成构建产物；已发布的版本不会自动覆盖。

聊天附件支持图片、文本、PDF 与部分 Office 文档，不支持直接附加 ZIP；压缩包可先放入项目目录，再在会话中引用。代理配置见 [反向代理说明](./REVERSE_PROXY_ADAPTATION.md)。
